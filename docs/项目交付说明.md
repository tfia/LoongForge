# LoongForge 项目交付说明

## 交付目标

LoongForge 用于复现“基于历史 GCC bug feature、LLM 语义组合、AFL++ 覆盖反馈”的 LoongArch GCC 编译器质量测试流程。交付对象是公司内部自有 GCC fork 的 CI/质量测试环境，不涉及网络安全测试、渗透测试或第三方目标测试。

## 交付包包含

- `README.md`：项目入口和文档索引；
- `docs/复现指南.md`：新环境从源码、工具链到 LLM/AFL 闭环的复现步骤；
- `docs/阶段结果摘要.md`：当前稳定结果和指标解释；
- `docs/AFL_GCC_CI_使用说明.md`、`docs/AFL反馈闭环阶段评估.md`、`docs/GCC源码覆盖率使用说明.md`：专项说明；
- `scripts/`：源码拉取、binutils/GCC 构建、AFL showmap/fuzz、覆盖统计、长程闭环和基本测试脚本；
- `gcc-bugzilla-loongarch/`：GCC Bugzilla 语料归档工具；
- `extract-llm/`、`group-llm/`、`instan-llm/`：三阶段 LLM 管线；
- `data/curated/group-llm/`：可复现实验用的精简 GroupLLM 快照；
- `seeds/`、`seeds-cxx/`：AFL++ 冒烟测试种子；
- `.env.example` 和 `group-llm/.env.example`：环境变量模板；
- `third_party/SOURCES.lock` 和 `.gitmodules`：GCC/binutils-gdb 源码版本锁定信息。

## 交付包不包含

以下内容不会进入交付包，需要在内部环境重新生成或按需单独归档：

- `.env`、API key、provider token 等本地密钥；
- `build/`、`install/`、`install-afl/`、`install-gcov/` 等构建和安装产物；
- `logs/`、`out/`、`extract-llm/out/`、`group-llm/out/`、`instan-llm/out/` 等本地运行输出；
- `gcc-bugzilla-loongarch/archive*/` 等本地爬取归档；
- `src/gcc-upstream/`、`src/binutils-gdb/` 的完整源码实体；交付包只保留锁定版本，源码由 `scripts/bootstrap-sources.sh` 在新环境拉取；
- `docs/internal/` 内部过程文档。

## 建议验收顺序

1. 解压交付包；
2. 阅读 `docs/复现指南.md`；
3. 运行 `./scripts/run-basic-tests.sh` 做纯代码基本测试；
4. 执行 `./scripts/bootstrap-sources.sh` 拉取锁定源码；
5. 构建普通 binutils、AFL++ 插桩 GCC；
6. 运行 `./scripts/verify-gcc-afl.sh` 验证插桩和 AFL++；
7. 按需运行 ExtractLLM/GroupLLM/InstanLLM 或直接消费 `data/curated/group-llm/` 快照；
8. 运行 `scripts/run-afl-feedback-loop.py` 做 1-3 轮质量测试闭环。

## 质量边界

本项目只生成和执行编译器测试程序。AFL++ 的 `saved_crashes` 在本项目中表示 GCC 前端 ICE 或进程崩溃候选；发现后需要复现、最小化，并与已有历史 bug PoC 和 signature 对比，不能直接宣称发现新问题。
