# LoongForge 阶段结果摘要

## 项目定位

LoongForge 面向团队自有 LoongArch GCC fork 的编译器质量测试。核心目标是用历史 bug 提炼出的语义 feature，经 LLM 组合生成新测试程序，再用 AFL++ 插桩 GCC 的 edge coverage 反馈下一轮 feature 选择，从而提高 CI 语料的覆盖能力并尽早发现 ICE、崩溃、超时和覆盖回退。

## 已完成能力

- LoongArch64 普通 binutils 构建脚本；
- AFL++ 插桩 GCC 构建脚本，覆盖 `loongarch64-linux-gnu-gcc/g++` 与 `cc1/cc1plus`；
- 单样例 `afl-showmap` wrapper、语料累计 coverage wrapper、AFL++ fuzz 启动器和报告脚本；
- GCC Bugzilla LoongArch 语料归档工具；
- ExtractLLM：从 Bugzilla report 提取结构化 compiler feature；
- GroupLLM：把多个历史 feature 组合成可实例化 feature group；
- InstanLLM：生成完整 C/C++ 编译器测试程序，并用 AFL++ wrapped GCC 评估 edge coverage；
- AFL feedback loop：把新增 AFL union edge 转换为 feature reward，反馈给下一轮 GroupLLM 采样；
- 可选 native `afl-fuzz` 阶段：把 LLM 生成的 covered 程序作为 seed，运行 AFL++ 原生变异并把 queue coverage 合入 feedback；
- gcov 口径源码行/函数覆盖重放脚本。

## 指标解释

- AFL edge coverage：来自 AFL++ instrumentation 的控制流边覆盖，用于 fuzz/corpus admission 和 feedback；
- union edge：当前 corpus 触发的去重 edge 集合，适合同一构建、同一前端、同一编译选项下比较趋势；
- gcov 源码覆盖：GCC 源码行/函数/分支覆盖，适合质量汇报；
- `covered`：生成程序经过 AFL++ wrapped GCC 前端评估并产生非空 edge map；
- `rejected`：模型或本地规则判断 feature 组合不兼容，不等于系统失败；
- ICE/crash：质量缺陷候选，需要复现、最小化和历史 PoC 去重。

## 后续建议

1. 在公司内部 provider 上先做 8-16 个 group 的 smoke test，确认 ready 率和 parser/API error；
2. 正式批次每次 1-3 轮，记录 union edge 增长、covered 数、ICE、provider error 和耗时；
3. 优先补齐 diagnostic、assembly-scan、Fortran/asm/RTL 等专用 harness；
4. 把 effective corpus admission 接入 CI：新增 edge 或强 oracle 的样例优先入库；
5. 对 ICE-like crash 建立 signature 去重和历史 bug PoC 对照表。
